# راهنمای متغیرهای محیطی — Netlify، پنل ادمین و ملی‌پیامک

این راهنما دقیقاً همان چیزی است که کدِ همین مخزن می‌خواند: `server/admin-config.mjs`، `server/order-sms.mjs` و `server/storage-blobs.mjs`. هر متغیری که اینجا نیست، سایت نمی‌خواند — پس لازم نیست ساخته شود.

> **قاعدهٔ طلایی:** هیچ‌کدام از این‌ها نباید با `VITE_` شروع شوند. هر متغیری که `VITE_` داشته باشد در بیلد داخل جاوااسکریپت عمومی می‌رود و برای همه قابل خواندن است. همهٔ موارد زیر فقط سمت سرور (Netlify Functions) خوانده می‌شوند.

---

## ۱) کجا تعریف کنیم

Netlify → **Site configuration → Environment variables → Add a variable**

برای هر متغیر:

| فیلد | مقدار پیشنهادی |
| --- | --- |
| **Key** | نام دقیق، حروف بزرگ، مثل `ADMIN_EMAIL` |
| **Value** | مقدار همان جدول‌های پایین |
| **Scopes** | `All` (یا حداقل `Functions`) — پیش‌نمایش‌ها هم باید کار کنند |
| **Secret** | برای گذرواژه‌ها، هش، کلید API و کلید امضا: **روشن** |

نکته‌های مهم:

- متغیرها **بعد از تغییر، نیاز به دیپلوی تازه دارند** (Deploy → *Clear cache and deploy site*)؛ تا آن موقع تابع‌ها مقدار قدیمی را می‌بینند.
- `$` در مقدارها مشکلی ندارد؛ آن را داخل `"` یا `'` نگذارید (در Netlify مقدار را همان‌طور که می‌نویسید ذخیره می‌شود).
- اگر پنل را در محیط آزمایشی هم می‌خواهید، Scope همان متغیر را `Deploy previews` هم بگذارید — با این تفاوت که محتوا و سفارش‌های پیش‌نمایش **خودکار** در فروشگاه جدا (`cahen-admin-preview`) ذخیره می‌شوند و به دادهٔ اصلی دست نمی‌زنند.

## ۲) پنل ادمین (`/shenataisoni`)

بدون این‌ها پنل بالا می‌آید ولی «پیکربندی‌نشده» می‌ماند و ورود ممکن نیست.

| متغیر | الزامی | مقدار / نمونه | نوع |
| --- | --- | --- | --- |
| `ADMIN_EMAIL` | ✅ | `info@cahen.ir` (همان ایمیلی که با آن وارد می‌شوید) | معمولی |
| `ADMIN_PASSWORD_HASH` | ✅ (توصیه‌شده) | خروجی `npm run admin:hash` — شکلش: `scrypt$32768$8$1$<۳۲ کاراکتر hex>$<۱۲۸ کاراکتر hex>` | **Secret** |
| `ADMIN_PASSWORD` | ⛔ (فقط جایگزین موقت) | مثلاً `kaveh-19-shabane-1404` — حداقل **۱۲ نویسه** | **Secret** |
| `ADMIN_SESSION_SECRET` | ✅ | یک رشتهٔ تصادفی **۳۲ نویسه یا بیشتر** | **Secret** |
| `ADMIN_NAME` | اختیاری | `کاهن` — نامی که در گوشهٔ پنل دیده می‌شود | معمولی |
| `ADMIN_SESSION_HOURS` | اختیاری | `8` (بازهٔ مجاز ۱ تا ۷۲) | معمولی |
| `ADMIN_TEAM` | اختیاری | JSON برای ویرایشگر/بیننده — نمونه پایین | **Secret** |
| `ADMIN_BLOB_STORE` | اختیاری | `cahen-admin` (پیش‌فرض همین است، فقط اگر می‌خواهید نام دیگری بگذارید) | معمولی |
| `ADMIN_COOKIE_SECURE` | اختیاری | `false` — روی Netlify لازم نیست، چون HTTPS و `X-Forwarded-Proto` هست | معمولی |

### ساخت `ADMIN_PASSWORD_HASH` (بدون اینکه گذرواژه جایی ذخیره شود)

روی کامپیوتر خودتان، داخل همین مخزن:

```bash
npm run admin:hash -- "یک عبارت طولانی و یکتا"
```

یا بدون آرگومان تا در history ترمینال هم نماند (ورودی نمایش داده نمی‌شود):

```bash
npm run admin:hash
```

سپس **کل خروجی** را (از `scrypt$` تا آخر) در مقدار `ADMIN_PASSWORD_HASH` بگذارید. این هش برای هر بار اجرا متفاوت است و طبیعی است.

> چرا هش بهتر از `ADMIN_PASSWORD` است؟ گذرواژهٔ خام هیچ‌وقت در متغیر محیطی نمی‌نشیند و کسی که به داشبورد Netlify دسترسی پیدا کند، گذرواژهٔ قابل استفاده نمی‌بیند.

قواعدی که کد روی گذرواژه اعمال می‌کند (اگر `ADMIN_PASSWORD` بگذارید): حداقل ۱۲ نویسه، نباید بخشی از ایمیل باشد، نباید تکرار یک حرف باشد، و نباید با `password` / `passw0rd` / `qwerty` / `123456` / `admin` شروع شود.

### ساخت `ADMIN_SESSION_SECRET`

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

خروجی حدود ۶۴ کاراکتر است، مثلاً:

```
q3Vn2t7cQ0mZJ8sYb1pXe4rLk9wHd6aTf5gUo2iNc8vB3mS0zRx7jKpYhE1qWnA
```

⚠️ اگر رشته‌ای بگذارید که یکی از واژه‌های `secret`، `test`، `demo`، `example`، `change-me`، `replace-me` در آن باشد، برنامه آن را **نمی‌پذیرد** و پیام خطا می‌دهد. یعنی چیزی مثل `cahen-secret-key` رد می‌شود.

### `ADMIN_TEAM` — فقط اگر همکار اضافه می‌کنید

یک آرایهٔ JSON در **یک خط**:

```json
[{"email":"editor@cahen.ir","name":"سردبیر","role":"editor","passwordHash":"scrypt$32768$8$1$...$..."}]
```

- `role` فقط `editor` یا `viewer` مجاز است؛ نقش `owner` همیشه از `ADMIN_EMAIL` می‌آید.
- برای هر نفر جداگانه `npm run admin:hash` بگیرید.
- حساب‌هایی که از داخل خود پنل ساخته می‌شوند (تب Administrators) در Blobs ذخیره می‌شوند و نیازی به متغیر محیطی ندارند؛ حساب‌های `ADMIN_TEAM` در پنل فقط‌خواندنی‌اند و فقط با عوض‌کردن متغیر تغییر می‌کنند.

## ۳) ملی‌پیامک (پیامک سفارش‌های فرم همکاری)

سایت سفارش را **اول ذخیره** می‌کند و بعد پیامک می‌فرستد؛ اگر این‌ها ناقص باشند سفارش گم نمی‌شود و با وضعیت `pending` می‌ماند تا از پنل (تب سفارش‌ها) یا با اسکریپت ساعتی دوباره فرستاده شود.

| متغیر | الزامی | مقدار / نمونه | نوع |
| --- | --- | --- | --- |
| `MELIPAYAMAK_USERNAME` | ✅ | نام کاربری حساب ملی‌پیامک، مثلاً `09123456789` یا نام کاربری که در پنل ملی‌پیامک دارید | **Secret** |
| `MELIPAYAMAK_API_KEY` | ✅ (یکی از این دو) | کلید API از پنل ملی‌پیامک (اگر حساب شما کلید دارد، این را ترجیح دهید) | **Secret** |
| `MELIPAYAMAK_PASSWORD` | فقط جایگزین | گذرواژهٔ پنل ملی‌پیامک، اگر حساب کلید API ندارد | **Secret** |
| `MELIPAYAMAK_PATTERN_CODE` | ✅ | کد الگوی تأییدشده در پنل ملی‌پیامک (مثلاً `123456`) | معمولی |
| `ORDER_MANAGER_PHONE` | ✅ | موبایل مدیر که پیامک سفارش باید برود، مثلاً `09123456789` (شکل `+98912...` هم پذیرفته می‌شود و خودکار تبدیل می‌شود) | **Secret** |

### الگوی پیامک (همان چیزی که مشتری می‌بیند)

ارسال **فقط با الگو** انجام می‌شود، نه پیام آزاد. متن الگو در پنل ملی‌پیامک این است:

```
درخواست همکاری جدید CAHEN
نام: {0}
موبایل: {1}
CAHEN
```

و سایت فقط دو مقدار را در همان ترتیب پر می‌کند:

| اسلات | مقدار | منبع |
| --- | --- | --- |
| `{0}` | نام و نام خانوادگی | فیلد «نام» در فرم همکاری |
| `{1}` | شمارهٔ موبایل | فیلد «موبایل» در فرم، به شکل محلی `09…` |

گیرندهٔ پیامک `ORDER_MANAGER_PHONE` است و هیچ مقدار دیگری از فرم (ایمیل، خدمت، توضیح، کد سفارش) به سرویس نمی‌رود.

نکته‌های عملی:

- **کد الگو** را از پنل ملی‌پیامک بردارید و در `MELIPAYAMAK_PATTERN_CODE` بگذارید؛ این همان `bodyId` است.
- از این نسخه به بعد **هیچ شمارهٔ فرستنده‌ای لازم نیست**؛ خط به خود الگو گره خورده است. اگر `MELIPAYAMAK_FROM` را از قبل داشتید، می‌توانید پاکش کنید — دیگر خوانده نمی‌شود.
- اگر هر دو `MELIPAYAMAK_API_KEY` و `MELIPAYAMAK_PASSWORD` را بگذارید، **کلید API** برنده است.
- اگر نام یا موبایل خالی باشد، پیامک **فرستاده نمی‌شود** و سفارش با وضعیت `pending` می‌ماند تا از پنل کامل و دوباره ارسال شود.
- `ORDER_MANAGER_PHONE` باید موبایل باشد؛ شمارهٔ ثابت برای دریافت پیامک مناسب نیست.
- ترتیب دو مقدار در تست `npm run sms:check` قفل شده است: اگر الگو را عوض کردید و ترتیب اسلات‌ها تغییر کرد، همان تست باید به‌روز شود.

## ۴) جدول کامل و خلاصه (کپی-پیست)

حداقل مجموعهٔ کاری برای «پنل + پیامک» روی Production:

```dotenv
ADMIN_EMAIL=info@cahen.ir
ADMIN_PASSWORD_HASH=scrypt$32768$8$1$<salt>$<hash>
ADMIN_SESSION_SECRET=<64 کاراکتر تصادفی>
ADMIN_SESSION_HOURS=8

MELIPAYAMAK_USERNAME=<نام کاربری ملی‌پیامک>
MELIPAYAMAK_API_KEY=<کلید API>
MELIPAYAMAK_PATTERN_CODE=<کد الگو>
ORDER_MANAGER_PHONE=09123456789
```

اختیاری‌ها:

```dotenv
ADMIN_NAME=کاهن
ADMIN_TEAM=[{"email":"editor@cahen.ir","name":"سردبیر","role":"editor","passwordHash":"scrypt$..."}]
ADMIN_BLOB_STORE=cahen-admin
ADMIN_COOKIE_SECURE=false
```

این‌ها را **در Netlify نسازید** (خود Netlify می‌گذارد یا فقط برای سرور محلی معنا دارند):

| متغیر | چه کسی می‌گذارد | کاربرد |
| --- | --- | --- |
| `CONTEXT` | Netlify | تشخیص پیش‌نمایش برای فروشگاه جدا |
| `NETLIFY_BLOBS_CONTEXT` | Netlify | دسترسی خواندنِ تازه (strong consistency) |
| `SITE_ID` | Netlify | شناسایی سایت، اعتماد به هدرهای پروکسی |
| `NETLIFY` | Netlify | همان |
| `TRUST_PROXY` | فقط سرور Node محلی | اگر پشت nginx هستید `true` |
| `PORT` | فقط سرور Node محلی | پیش‌فرض `4173` |

## ۵) بعد از تنظیم، چطور مطمئن شویم کار می‌کند

1. **دیپلوی تازه بگیرید:** Deploys → *Trigger deploy* → *Clear cache and deploy site*. (بدون دیپلوی، تابع‌ها متغیر تازه را نمی‌بینند.)
2. **پنل را باز کنید:** `https://cahen.ir/shenataisoni`
   اگر چیزی کم باشد، خودِ صفحهٔ ورود و بالای پنل فهرست مشکلات پیکربندی را نشان می‌دهد — همان پیام‌هایی که `admin-config.mjs` تولید می‌کند.
3. **از API بپرسید:**

   ```bash
   curl -s https://cahen.ir/api/admin/session
   ```

   - سالم: `{"ok":true,"configured":true,"sessionHours":8,"admin":null,...}`
   - ناقص: `configured:false` و داخل `issues` می‌گوید کدام متغیر مشکل دارد (مثلاً «ADMIN_SESSION_SECRET باید حداقل ۳۲ نویسه…»).
4. **ورود و یک تغییر کوچک** در پنل بزنید (مثلاً یک فاصله در متن) و ذخیره کنید؛ اگر ذخیره شد، Blobs درست وصل است.
5. **تست پیامک:** فرم همکاری سایت را یک‌بار با شمارهٔ خودتان پر کنید (سقف ۳ سفارش در ساعت برای هر آی‌پی). بعد در پنل → تب «سفارش‌ها» وضعیت را ببینید:
   - `sent` یعنی پیامک رفت (شناسهٔ ارجاع هم ذخیره می‌شود).
   - `pending` یعنی تنظیمات ملی‌پیامک ناقص بود؛ در همان ردیف دکمهٔ «ارسال دوباره» هست.
   - `failed` یا `partial` یعنی ملی‌پیامک خطا داد؛ متن خطا ذخیره می‌شود.
   حتی اگر کسی پنل را باز نکند، اسکریپت زمان‌بندی‌شدهٔ `retry-orders` هر ساعت تا ۱۰ سفارش معلق را دوباره می‌فرستد.

## ۶) امنیت و نگهداری

- `ADMIN_PASSWORD_HASH`، `ADMIN_PASSWORD`، `ADMIN_SESSION_SECRET`، `ADMIN_TEAM`، `MELIPAYAMAK_*` و `ORDER_MANAGER_PHONE` را همیشه با کلید **Secret** ذخیره کنید.
- `.env` محلی را هرگز کامیت نکنید؛ `.gitignore` همین الان `.env*` را می‌گیرد و فقط `.env.example` (بدون مقدار) در مخزن است.
- **چرخش کلید امضا:** `ADMIN_SESSION_SECRET` را عوض کنید → همهٔ دستگاه‌ها بلافاصله از پنل خارج می‌شوند. برای تعویض گذرواژه، هش تازه بسازید و `ADMIN_PASSWORD_HASH` را جایگزین کنید.
- اگر می‌خواهید پنل حتی برای دارندگان لینک هم باز نشود، از Netlify → *Site protection* (Password protection یا راه‌حل SSO) استفاده کنید؛ این یک لایهٔ اضافه است، نه جای رمز پنل.
- هر سال یک‌بار: گذرواژهٔ پنل، کلید API ملی‌پیامک و `ADMIN_SESSION_SECRET` را نو کنید.
